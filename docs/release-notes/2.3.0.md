# v2.3.0

`--fronting-domain` now fronts **unconditionally**. Once set, every direct
WebSocket connection (including pool pre-connects) presents the fronted SNI
first — no plain-SNI probe, no sticky window, no per-DC failure cooldown. A
fronted failure still falls back to one plain attempt before the rest of the
fallback ladder, so a network where fronting stops working self-heals.

Previously fronting was detection-gated: the proxy sent the real
`kws{N}.web.telegram.org` SNI first and only retried fronted after the
handshake failed, then kept fronting in a global sticky window after a success.
On networks where the plain SNI is reset by DPI, every connection donated a
doomed attempt to the censor first; worse, the sticky window was global, so one
DC's fronting failure deactivated fronting for every other DC until a new
success re-armed it.

## Removed flags

| Flag | Env var | Replacement |
| --- | --- | --- |
| `--fronting-cooldown` | `TG_FRONTING_COOLDOWN` | none — no sticky window exists |
| `--fronting-fail-cooldown` | `TG_FRONTING_FAIL_COOLDOWN` | none — fronting is always attempted |

Deployments passing either flag will fail to start with an unknown-argument
error; remove them from the command line, environment or unit file.

## Cost

On a network where fronting can never succeed (e.g. the DC IP is blocked
outright, not just by SNI), every connection now pays one fronted attempt
before the plain one, instead of skipping fronting during its failure
cooldown. The `--dc-ip` guidance for such networks is unchanged: leave it
unset so the direct path is never attempted.
